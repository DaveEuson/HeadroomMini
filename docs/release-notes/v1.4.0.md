## HeadroomMini v1.4.0

### Headroom Mini (ESP32-S3)

- **Actions — the board as a shortcut pad for Claude Code.** A sixth screen:
  swipe up/down to pick a shortcut, tap to fire it at the computer running
  Claude Code. Ships with Voice mode (`space`), Mode toggle (`shift+tab`), and
  Interrupt (`escape`). The screen tells you whether anything is listening, so
  a dead button is never a mystery. **Requires the v1.4.0 companion started
  with `--actions`** — the board queues presses, the companion types them.
- **Running out puts the countdown on screen by itself.** The moment a window
  hits 100% is when the only number worth reading is how long until you can
  work again, and it's also when you're least likely to go hunting for it — so
  the board switches to the countdown on its own. It reads "back in" rather
  than "resets in", and an exhausted window outranks a sooner-resetting one you
  haven't touched. Once per episode: tap away and it stays away until that
  window resets and is spent afresh.
- **Board-served pages now match the device.** The settings, alerts, and update
  pages use the same paper-side palette as the screen instead of drifting from
  it.
- **`/api/status` says more.** Reports the active screen (`screen`,
  `screen_name`) and each window's `resets_at`, so a countdown that won't count
  or a screen that won't switch is diagnosable without standing over the board.

Upgrading over OTA reveals the Actions screen once, automatically. If you
un-check it in settings afterwards, it stays gone.

### Companion

- **`--actions`** collects button presses from the board and replays them as
  keystrokes on this computer. Off unless you ask for it — synthesising
  keypresses is a real capability, so it is never enabled behind your back.
- The board only queues an action on a **physical tap**; nothing on the network
  can inject one, and unclaimed presses expire after 15 seconds so a tap made
  while the companion was closed can't fire minutes later. The keystroke lands
  in **whatever window is focused**, which is the reason it's opt-in.
- Remap any button via `companion.config.json`:
  `{ "action_keys": { "cancel": "ctrl+c" } }`
- Platform notes: **Windows** works as-is; **macOS** needs Accessibility
  permission for whatever runs the companion (System Settings → Privacy &
  Security → Accessibility); **Linux** needs `xdotool`.

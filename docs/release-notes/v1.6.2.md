## Yoyu v1.6.2

**Companion-only fix. If you downloaded the companion for v1.6.1, replace it.**
The firmware is unchanged apart from its version number — there is nothing to
gain by updating the board.

### v1.6.1's auto-start fix only worked in half the downloads

v1.6.1 claimed the companion would clear out auto-start entries left by older
names of this product — the ones that quietly launch a second companion at every
login, fight your board for the same Claude account, and leave it rate limited
and showing nothing.

It did that in `YoyuCompanion-cli`, and **not** in `YoyuCompanion`, the tray app.
The tray app has its own startup path that never reached the cleanup. It is also
the download the setup page points everyone at, so the people most likely to be
carrying a stale entry are exactly the ones the fix missed.

Both downloads clear them now.

Because the tray app has no console to print to, it tells you in the menu's
status line and, where your desktop supports it, with a notification. A file
disappearing out of your Startup folder unannounced would be worse than the
problem it solves.

### How this got missed, and what changed so it doesn't happen again

v1.6.1's fix was tested against the source, which was correct. What was wrong
was which of the two startup paths reached it — something only running the
actual published binaries would show. That is now how it is checked, and there
is a test asserting every entry point performs the sweep.

### Upgrading

**Download the companion again** from this release and replace the copy you have.
On Windows it will clear any stale entry the next time it starts.

The firmware needs nothing. If you update it anyway, `/update` or a re-flash both
keep your Wi-Fi, login and settings, and the board will report `v1.6.2` — no
behaviour changes.

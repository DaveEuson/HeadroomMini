## Yoyu v1.6.1

Fixes for two things that made the board look broken when it wasn't. Nothing
changes on screen — same eight screens, same kitsune, same behaviour as v1.6.0.

### "Install update" no longer says there's nothing to install

The update page would tell you a new version was available, offer the button,
and then answer *"Already on the latest version"* when you pressed it. The board
was fine; the check behind the button was failing.

It checked twice — once to draw the page, once more when you clicked — and the
second check is the one that kept failing. A failed check was indistinguishable
from "you're up to date", which is the wrong assumption of the two. It now
retries, and the answer from drawing the page is reused for a minute, so one
click costs one round trip instead of two.

Measured on a real board while fixing it: the first attempt failed and the retry
succeeded on the very first run, so this was happening far more often than
"occasionally".

### Two companions could be running at every login without you knowing

If you've had this installed since before it was called Yoyu, an auto-start
entry from the old name may still be in your Startup folder, quietly launching a
second companion every time you log in. `--uninstall` didn't know that name, so
it reported success and left it there.

That is worse than untidy. **Two companions polling Anthropic on one account is
what gets your board rate limited** — it stops showing numbers, backs off for
longer and longer, and there is nothing on screen to tell you why.

The companion now clears out entries from every name this project has ever used,
**when it starts**, not only when you ask it to uninstall — you shouldn't need to
know about a stale file from two renames ago to get your board working. It only
touches files it recognises as its own, never the current one, and it prints
what it removed.

Windows only. The macOS and Linux service names never changed.

### The board can now tell you why it's empty

`/api/status` gained three fields, so a board that isn't showing numbers can be
diagnosed without standing over it:

- `poll_status` — the same message the meters screen prints, e.g.
  `"rate limited - waiting ~10m"` or `"login expired - re-pair"`. Previously
  this only ever existed as pixels on the panel.
- `release_check` — whether the update check is working, how many attempts it
  took, and free heap either side of it.
- `board` — which panel this firmware drives.

```
curl -s http://yoyu.local:8080/api/status
```

### Groundwork: a second board

Support for the Waveshare **ESP32-S3-Touch-AMOLED-2.16** is being built. This
release contains the pin definitions, the build target and the display driver,
but **no AMOLED firmware is published yet** and the setup page still offers only
the 2" LCD board. Nothing to do; nothing changes for you.

The reference panel is provably untouched by that work: the layout maths is the
identity for every one of its 240×320 coordinates.

### Upgrading

Over the air from `/update`, or re-flash from the setup page. Both keep your
Wi-Fi, login and settings.

**Update the companion too** — the auto-start fix lives there, not in the
firmware, so a board updated on its own will still be fighting a stale companion
for the account.

## Yoyu v1.6.3

**If your board signs itself in — the "runs without your computer" mode — update
both the board and the companion, and pair once more.** It has been logging you
out of Claude Code roughly once a day, and this release is what stops it.

### Your board was signing you out of Claude Code

Not occasionally, and not by accident. About once a day, working exactly as
designed.

Claude logins use rotating refresh tokens: spending one invalidates it and
issues a replacement. Pairing gave the board a copy of the same token Claude
Code holds on your computer, and the board's access token lasts about eight
hours — so roughly three times a day it renewed, and whichever of the two
renewed second was left holding a dead credential. Sometimes that was the board
("login expired — re-pair"). Sometimes it was your computer, which is worse,
because nothing explains it.

**The board no longer holds a refresh token at all.** It gets a short-lived
access token it cannot renew, and the companion — which has always held the
refresh token, because Claude Code does — hands it a fresh one whenever it runs.
A board upgrading to this release also erases the refresh token already in its
flash rather than leaving a spendable credential sitting there unused.

The advice this replaces was "give the board its own Claude account", which
costs several times what the board does. Sharing one account is the normal case,
so it had to be the safe one.

### What that costs, plainly

**The board now keeps going for several hours after your computer sleeps, rather
than indefinitely.** Leave the computer off overnight and the board pauses in
the small hours and catches up when you sit down.

That limit is real and we would rather state it than keep meeting it by breaking
the login the board borrowed. Running truly independently needs a credential the
board is allowed to own, and getting one means a fresh sign-in — the throttled
path this whole project exists to avoid.

Nothing changes if you feed the board from the companion (the default). That
mode never held a token in the first place.

### The board stops competing with your computer for the rate limit

Both read the same account, and Anthropic rate-limits per account — so a board
polling while a companion pushed spent the budget twice for one set of numbers,
and the two throttled each other. The board now stands down while a companion is
feeding it, and resumes on its own when the pushes stop.

### Pairing actually works now

Four bugs, all found by trying to pair rather than by reading the code:

- **The code no longer scrolls away.** If you had auto-rotate on, the board kept
  cycling screens while pairing, so the code appeared and was painted over
  seconds later. Every other screen — Timer, Actions, Settings — already stood
  down during pairing; this one did not.
- **The screen wakes first.** A dimmed or face-down board used to draw the code
  onto a dark panel and report success.
- **An expired code says so**, instead of "couldn't reach the board". The board
  answered with a status code *and* a reason, and the reason was being thrown
  away.
- **`--pair-code` works at all.** It re-entered pairing mode before checking,
  which minted a *new* code and guaranteed a mismatch. There is also now
  `--pair-start`, which puts a code on screen and exits, so pairing works from a
  terminal that can't prompt.

### When something is wrong, it now says what

`/api/status` gained `poll_status`, `screen_off`, `backlight`, `pairing`,
`board` and `release_check`, so a board that isn't showing numbers can be
diagnosed without standing over it:

```
curl -s http://yoyu.local:8080/api/status
```

Every one of those was added because something was diagnosed wrongly without it.
A board drawing correctly onto a dark panel looks identical, over the network,
to one that is fine.

And "can't find your Claude login" is now four different messages, because it
was four different situations — not installed, never signed in, an unreadable
file, or a login that has been **cleared** (tokens blanked, everything else
intact). That last one is what a second device sharing your account produces,
and it was being reported as "you're not signed in" to people whose Claude Code
was working in the next window. Each now ends in the exact commands to type.

### Upgrading

1. **Update the board** — `/update`, or re-flash from the setup page.
2. **Replace the companion** with the download from this release.
3. **Pair once more** if your board signs itself in. It will ask: the screen
   says *"needs pairing once more"*. After that it never asks again — the
   companion renews it automatically, forever.

Wi-Fi, settings and history survive all of it.

## HeadroomMini v1.5.0

Two screens answering questions the board couldn't: **where do I configure
this**, and **where did my tokens actually go**.

### Headroom Mini (ESP32-S3)

- **Settings — the board finally tells you where it lives.** A working board
  printed its own address nowhere; `ip:port` appeared only on the
  not-yet-set-up and error screens, so once everything worked there was no
  route from the device to `/settings`, `/alerts` or `/update`. The new screen
  shows the address as the largest type on it, plus the firmware version.
- **…and lets you change the screen rotation without a browser.** Swipe to move
  the cursor, tap to toggle a row. Three toggles are refused with a reason on
  screen: this screen itself, the power-on default, and anything that would
  leave fewer than two screens — so the address can't be tapped out of
  existence. Those guards run in the disable direction only, so a row switched
  off from the web form can still be switched back on from the device, and
  `/settings` in a browser can still do all three.
- **Projects — which project is eating your week.** The top five by share of
  the trailing 5 hours, with `+N more` when others fall below the cut.
  Nested directories roll up: opening a repo, a subdirectory of it, and a
  package inside that is one project, not three.

  This is the one screen that can only ever describe **this computer**, and it
  says so. Anthropic's usage endpoint reports account-wide windows with no
  per-project breakdown, so the ranking is built from Claude Code's own session
  logs, which are local. Work done from another machine won't appear. Shares
  are percentages of measured tokens rather than of a plan limit, so the
  ranking stays honest even where an absolute percent-of-limit would be an
  estimate.

Upgrading over OTA reveals both new screens once, automatically. Un-check
either afterwards and it stays gone.

### Companion

- Sends per-project shares with every push. Nothing to enable, and it works on
  both the live and estimated paths — the live usage endpoint has no
  per-project data to offer, so the two answer different questions and aren't
  expected to agree.
- Projects are identified by each session's own working directory rather than
  the folder name under `~/.claude/projects`. Those folder names are
  path-mangled and can't be reversed: `H--Projects-Kiosk-Grand` is the project
  "Kiosk Grand", and nothing in the name distinguishes a `-` that was a path
  separator from one that was in the folder name.
- Reading the logs skips files last written before the window being measured,
  so this doesn't add a full scan of every project you've ever opened to each
  poll.

### Notes

- Requires the v1.5.0 companion for the Projects screen. An older companion
  simply omits the data and the screen says so rather than showing a stale
  ranking.
- `/api/status` now also reports the project shares and how long ago they
  arrived, so a ranking stuck on this morning is diagnosable without standing
  over the board.
